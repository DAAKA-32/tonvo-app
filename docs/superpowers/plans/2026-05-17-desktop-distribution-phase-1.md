# Cue Desktop — Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship installable Cue Desktop binaries (Windows .exe, macOS .dmg, Linux AppImage + .deb) downloadable from tonvo.com, auto-updating from a Vercel-hosted manifest pointing at GitHub Releases.

**Architecture:** A new `desktop/` workspace inside the Cue repo holds a Tauri 2 app. The Tauri shell loads a tiny offline-fallback HTML page, probes `https://app.tonvo.com/api/health`, and either navigates the webview to the live web app or shows a "reconnecting" screen. Two new Next.js routes (`/api/health`, `/api/desktop-release/[platform]`) and one new landing component (`DesktopDownloadHero`) complete the web-side changes. A GitHub Actions matrix workflow builds + publishes on `git tag desktop-v*`.

**Tech Stack:** Tauri 2 (Rust shell + native webview), Vite (builds the tiny TS shell), Vitest (unit tests for the 2 new TS modules), GitHub Actions matrix (windows-latest, macos-latest, ubuntu-22.04), `tauri-apps/tauri-action@v0`, GitHub Releases as binary host.

**Reference:** Spec at [docs/superpowers/specs/2026-05-17-desktop-distribution-phase-1-design.md](../specs/2026-05-17-desktop-distribution-phase-1-design.md). Re-read it before starting.

**Prerequisite — user must do this once before Task 1:**
1. Install Rust: `winget install Rustlang.Rustup` (Windows) or `https://rustup.rs` (Mac/Linux). Verify with `rustc --version` → should print `1.7x.x` or newer.
2. Install Microsoft C++ Build Tools (Windows only, required by Rust): `winget install Microsoft.VisualStudio.2022.BuildTools --override "--add Microsoft.VisualStudio.Workload.VCTools --quiet"`. Reboot after.
3. Confirm Node ≥ 20 with `node --version`.

```ts
const TARGET = import.meta.env.VITE_DESKTOP_TARGET ?? "https://app.tonvo.com";
const HEALTH = `${TARGET}/api/health`;
const PROBE_TIMEOUT_MS = 1500;

async function probe(): Promise<boolean> {
  const ctrl = new AbortController();
  const t = setTimeout(() => ctrl.abort(), PROBE_TIMEOUT_MS);
  try {
    const r = await fetch(HEALTH, { signal: ctrl.signal, cache: "no-store" });
    return r.ok;
  } catch {
    return false;
  } finally {
    clearTimeout(t);
  }
}

let backoffMs = 3000;

async function boot(): Promise<void> {
  document.body.dataset.state = "booting";
  if (await probe()) {
    window.location.replace(TARGET);
    return;
  }
  document.body.dataset.state = "offline";
  backoffMs = Math.min(backoffMs * 1.5, 30_000);
  setTimeout(boot, backoffMs);
}

document.querySelector(".retry")?.addEventListener("click", () => {
  backoffMs = 3000;
  boot();
});

boot();
```

- [ ] **Step 6.2: Create the route handler**

`src/app/api/desktop-release/[platform]/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";
import fs from "node:fs/promises";
import path from "node:path";

export const runtime = "nodejs";
export const dynamic = "force-static";
export const revalidate = 60;

const ALLOWED_PLATFORMS = new Set([
  "windows-x86_64",
  "darwin-aarch64",
  "darwin-x86_64",
  "linux-x86_64",
]);

interface ManifestEntry {
  url: string;
  signature: string;
}

interface Manifest {
  version: string;
  notes: string;
  pub_date: string;
  platforms: Record<string, ManifestEntry>;
}

async function readManifest(): Promise<Manifest> {
  const p = path.join(process.cwd(), "public", "desktop-releases", "latest.json");
  const raw = await fs.readFile(p, "utf-8");
  return JSON.parse(raw) as Manifest;
}

export async function GET(
  _req: NextRequest,
  { params }: { params: Promise<{ platform: string }> },
) {
  const { platform } = await params;
  if (!ALLOWED_PLATFORMS.has(platform)) {
    return NextResponse.json({ error: "unknown platform" }, { status: 404 });
  }

  const manifest = await readManifest();
  const entry = manifest.platforms[platform];
  if (!entry) {
    return new NextResponse(null, { status: 204 });
  }

  return NextResponse.json({
    version: manifest.version,
    notes: manifest.notes,
    pub_date: manifest.pub_date,
    url: entry.url,
    signature: entry.signature,
  });
}
```

Note: Tauri's updater treats `204 No Content` as "you are up to date" — that's why missing platforms return 204, not 404. The 404 is reserved for malformed/unknown platform names.

export type OS = "windows" | "macos" | "linux" | "unknown";

const REPO_BASE = "https://github.com/tonvo/cue-desktop/releases";

export function detectOSFromUA(ua: string): OS {
  if (!ua) return "unknown";
  if (/iPhone|iPad|iPod|Android/i.test(ua)) return "unknown";
  if (/Windows/i.test(ua)) return "windows";
  if (/Mac OS X|Macintosh/i.test(ua)) return "macos";
  if (/Linux|X11/i.test(ua)) return "linux";
  return "unknown";
}

export function detectOS(): OS {
  if (typeof navigator === "undefined") return "unknown";
  return detectOSFromUA(navigator.userAgent ?? "");
}

export function downloadUrl(os: OS): string {
  switch (os) {
    case "windows":
      return `${REPO_BASE}/latest/download/Cue-Setup.exe`;
    case "macos":
      return `${REPO_BASE}/latest/download/Cue.dmg`;
    case "linux":
      return `${REPO_BASE}/latest/download/Cue.AppImage`;
    case "unknown":
    default:
      return `${REPO_BASE}/latest`;
  }
}

export function osLabel(os: OS): string {
  switch (os) {
    case "windows": return "Windows";
    case "macos": return "macOS";
    case "linux": return "Linux";
    default: return "your device";
  }
}
